## 一、为什么要补：原评测的两个盲区

原评测（[测评方案.md](测评方案.md)）的口径是：

- **检索侧只测到文档级**：Hit@K / MRR 判断"出处**文档**是否出现在召回里"；
- **生成侧只有端到端对答案**：LLM 评审拿"回答 vs 标准答案"打分。

这两个口径合起来回答"系统答得对不对"，但回答不了"**错的时候错在哪一层、对的时候是不是碰巧对**"。具体有两个盲区：

1. **文档命中 ≠ 块命中**。喂给模型的是 top-K 个**块**。出处文档命中了，但相关块排在第 4、被无关块挤掉，生成照样可能错——这时错会被记到"生成"头上，**归因错层**。
2. **答案对 ≠ 答案有据**。评审只对比回答与金标，不检查"回答是否由召回资料支撑"。模型用参数记忆**碰巧**答对，会判对（假绿）；编了个数字答错，会被当成"生成弱"去调 prompt，实际可能是检索没喂对料。

本项目真实的四轮迭代里，这两类问题都发生过：分块截断表格（块级问题）、路由跳库用记忆编造（无据回答），当时都是靠人工逐题归因发现的。本版把这些经验固化成可复跑的指标。

## 三、每个新指标怎么测

### 3.1 上下文精确率（块级）——"喂进来的料干不干净"

- **输入**：问题 + /rag/search 返回的 top-K 块（每块含文档标题、所属标题、内容前 600 字）。
- **判定**：评审 LLM（qwen-plus，temperature=0）对每块独立判 0/1——"该块内容能否支撑回答该问题（或其一部分）；其他手册、只有词面沾边的块 = 0"。
- **公式**：`precision@K = Σ(块相关) / K`；`precision@3` 只看前 3 块。
- **为什么单独看 @3**：top-1~3 是生成模型实际依赖的主力上下文，@K 里混进了"排后面无所谓"的块会稀释信号。
- **设计要点**：判定标准写明"其他**手册**的内容算不相关"——本考卷每题有唯一出处手册，跨手册命中即不相关，这让 LLM 判定有清晰边界。

### 3.2 信息点召回率——"该进来的信息进全了没"

- **信息点怎么来**：`信息点 = 答案关键词（人工金标） + 标准答案中正则抽取的数字（含单位）`，去重、上限 8 个。数字是本域的命根（判卷口径就是"数字完全一致才对"），所以数字自动补进信息点，不用逐题手写。
- **判定**：评审 LLM 逐点判 0/1——"该信息点能否在**任一**召回块中找到直接依据（换措辞算覆盖）"。
- **公式**：`召回率 = Σ(点覆盖) / 信息点数`。
- **和文档级 Hit 的分工**：Hit@K 管"书找对没"，信息点召回管"页码翻全没"。L3/L4 多规则题（费率+封顶+审批线三个点缺一不可）靠它定位"部分覆盖"。

### 3.3 忠实度（答案 vs 上下文）——"答案是不是从资料里长出来的"

- **输入**：问题 + 召回块 + 回答。
- **判定**：评审 LLM 打 0/1/2——2 = 关键数字/规则/结论均在资料中有直接依据；1 = 大体有据但含资料外补充；0 = 关键结论无依据（疑似编造或参数记忆）。
- **报告口径**：完全支撑率（=2 的比例）；不足 2 分的逐条列理由。
- **它和准确率的分工**：准确率=答案 vs 金标（对不对），忠实度=答案 vs 上下文（有没有据）。**答对但不忠实 = 碰巧对（危险信号）；答错但忠实 = 检索的锅**。两个交叉看，归因才不会错层。

### 3.4 误拒率——"不该拒的被拒了"

- **判定**：非 L5 可答题的回答命中拒答模式（"没有相关内容 / 知识库中没有 / 未收录 / 无法回答"等 20 个短语）即记误拒。
- **为什么用短语模式不用 LLM**：系统拒答话术固定（"知识库里没有相关内容。"），模式匹配足够且可复现；且模式表刻意收紧——普通答案里出现"知识库"三个字不会误判（比如"按知识库规定赔 135 元"不算拒答）。
- **为什么重要**：本系统的"切题闸门"（grader）历史上出过**误杀正确召回**的 bug（19 题被冤枉），当时的表象就是误拒。这个指标把这类故障从"准确率下降"里单独拉出来报警。

### 3.5 引用召回率 / 引用精确率——"[n] 溯源到底靠不靠谱"

- **数据来源**：/ai/chat 响应里的 sources（回答实际引用的文档列表，由"落库前正则回收 [n] 编号"机制产出）。
- **引用召回率**：出处文档出现在引用里的题目比例——引用了才算可溯源。
- **引用精确率**：`出处文档数(0/1) / 引用文档数`。引用 3 篇只有 1 篇是出处 → 0.33。**为什么惩罚多引**：审计场景里"引一堆看着相关的文档"和"没引"差不多糟——用户点开 [2] 发现文不对题，信任直接崩。
- **已知口径限制**：本考卷每题有唯一出处手册，"引用了其他手册"才扣分；真实场景一题可由多文档支撑时，此口径需要金标给出"合法引用集合"。

### 3.6 稳定性（重复运行）——"同一个问题问三遍，答案一不一样"

- **采集**：`run_eval.py --repeat 3`——每题用 3 个**全新会话**（不传 sessionId，无历史、无长期记忆干扰）问同样的问题，输入完全一致。
- **判定一致率**：3 次回答分别过金标评审，"3 次判定结果（对/不对）全一致"的题目比例。
- **答案文本相似度**：3 个回答两两 difflib 相似度取均值——比"判定一致"更细的粒度，能看出"都对但措辞漂移"。
- **为什么必须测**：生成链路 temperature=0.2（有意保留一点表达多样性），采样非零 → 同题不同答是**设计内行为**，但"判定结果"必须稳定。"输出飘没飘"这个问题，从感觉变成数字。

### 3.7 L5 干扰块数——"库外问题检索器还塞了多少垃圾"

- L5（库外题）的 /rag/search 召回块数均值。rerank 有 min_score=0.4 过滤，这个指标验证过滤是否真的把无关块挡在门外——挡不住的话，"拒答"就全靠生成侧的提示词硬撑，等于安全带只剩一根。

### 3.8 多轮题（L6，新题型）

原考卷全是单轮。新增 4 组两轮对话（每组 turn1 是独立可答的锚问题，turn2 是**指代/省略式追问**，脱离上文不可理解），共 8 行：

| 链 | turn1（锚） | turn2（追问考点） |
| --- | --- | --- |
| CS-MT-01 | 丢失件报案时限 | "要是已经超过**这个时间**才来报呢？"（指代消解 → 超时报案规则） |
| ST-MT-01 | 差异申诉期限 | "过了**这个期限**才发现多收了，还有救吗？"（指代 → FAQ 例外规则） |
| CS-MT-02 | 80 元未保价全丢赔多少 | "那**这单**要是当时保价了 1000 元呢？"（"这单"回指运费/货值 → 保价规则重算） |
| OP-MT-01 | 错分件怎么处理 | "要是发现**它**外包装也破了，还能正常扫进去吗？"（"它"回指 → 跨章节规则组合） |

- **判定**：追问行按金标评审（准确率），引用指标照算；**检索侧指标不算**——追问的真实检索发生在 /ai/chat 链路内部（改写后），API 不暴露，采集不到（这是链路可观测性的真实缺口，见 §8）。
- **设计纪律**：turn2 的标准答案全部从手册原文逐条核对（吸取 R4"考卷出错"的教训），每条追问在上文缺失时不可独立理解。

## 四、判卷 prompt 的设计原则

沿用前作"宁严勿宽"的口径，三条原则：

1. **判定边界写到可执行**：不说"判断相关性"，而是"其他手册的内容、词面沾边但主题无关 = 0"——给评审模型明确的判例式边界，而不是让它自由心证。
2. **数组输出与输入一一对应**：块相关性/信息点覆盖输出定长数组，脚本侧做长度校验与截齐，防止评审模型偷懒输出错位数组。
3. **temperature=0 + response_format=json_object**：评审本身必须稳定，否则"用不稳定的天平称稳定性"。

评审成本：三路评审（金标×3 次 + 检索侧 + 忠实度）× 56 行 ≈ 260 次调用，qwen-plus 量级 < 2 元；线程池 6 并发，评审阶段约 3 分钟。

## 五、脚本改动清单

**run_eval.py（采集）**
- `hits` 从"只存标题/分数"升级为**含块内容（截 800 字）**——分侧评审的原料；
- 新增 `--repeat N`：每题 N 个独立会话，`answers[]` / `chat_latencies[]` 全量落盘（`answers[0]` 同步写旧字段，老数据格式兼容）；
- 新增 L6 多轮链采集：turn1 开新会话拿 sessionId，追问续用同会话；追问行 `id` 带 `#2`、`turn>=2`、`hits` 留空（原因见 §3.8）。

**judge_and_report.py（评审与报告）**
- 评审从单路拆三路：金标评审（逐次回答）、检索侧评审（块相关+信息点覆盖，一次调用出两组数组）、忠实度评审；线程池 6 并发；
- 新增 §3 全部指标的聚合与"失败明细"表（不忠实 / 信息点缺失 / 块相关率低 / 误拒 / 引用可疑 / 判定不一致逐条列出）；
- 检索指标口径修正：`retrievable` 只含 `turn=1` 的行（L6 追问无独立检索，不能进 Hit@K 分母——否则会把命中率虚拉下来）；
- 老格式 raw_results（无块内容）自动跳过分侧指标，报告标注，不炸。

## 七、结果解读（跑完后填写）

### 7.1 最重要的发现：单次运行的 100% 掩盖了边缘题的摇摆

OP-L4-01（"到件 36 小时未出库，什么预警级别？"）在 round4 单次运行里**答对了**（48/48=100% 的组成部分）；本次 3 次重复运行答了**红/红/黄**——2 次错。手册规则：24h 未出库黄色（仓管员处理）、48h 红色（站长处理）；36 小时在区间内应为黄色。模型两次被"36 小时还没出库"的措辞带偏，直接匹配到 48h 红色那行。

这道题本次留下了一条**完整的分侧证据链**，每一层指标都指向同一个根因：

| 层 | 信号 |
| --- | --- |
| 文档级 Hit | ✅ 站点手册排第 1（100%） |
| 块级 | ⚠️ 相关块只有 1/5——**滞留件预警表块没进 top-K** |
| 信息点召回 | ⚠️ "站长、24、48小时"缺失——关键规则不在喂给模型的资料里 |
| 生成 | ❌ 两次把 36h 判成红色——资料没喂够，模型只能靠猜 |
| 忠实度 | ❌ 0 分——"红色预警"在资料中无依据（判卷原话） |
| 稳定性 | ❌ 0/0/2 摇摆 |

**这是整个分侧评测的价值证明**：如果只有端到端指标，我们看到的只是"这次错了 1 题"；分侧指标把"为什么错"（关键块没召回→模型无据猜答）和"有多危险"（单次跑可能对也可能错，正答率约 1/3）都摆了出来。round4 的 100% 不是假数据，但它是**单次采样**——对边缘题，单次采样会高估也会低估。

### 7.2 块级精确率 45.1% 怎么读：头部高质量，尾部噪声大

45.1% 单独看很吓人，但它必须和另两个数字成组读：

- **golden_rank 全部 = 1**：出处文档 46/46 排第 1；
- **@3（54.7%）> @K（45.1%）**：越靠前越相关。

合起来的图景：**top-1~2 几乎总是正确的块，第 3~5 位是"同手册相邻章节"的填充块**（主题相近、词面沾边，但不含答案——比如问报案时限，召回进来"报案材料"章节）。rerank 的 min_score=0.4 挡得住跨手册的远噪声，挡不住同手册的近噪声。

当前这个噪声**没有伤到正确率**（模型主要依赖前几块），但它是明摆着的优化空间，也是脆弱点储备——文档再厚一点，近噪声就会开始挤占有效块。可选动作：topK 5→3（反正 golden_rank=1）、min_score 试探性上调、或检索词改写时把数值/阈值类关键词（"36小时"“48小时”）带进 query。

### 7.3 判定一致率 95.8%：两个摇摆样本，两种来源

48 题 × 3 次，46 题判定完全一致。2 题摇摆，来源不同：

- **OP-L4-01（0/0/2）**：生成端摇摆——三次回答实质不同（见 §7.1）。
- **ST-L2-01（2/0/2）**：生成端+判卷端混合——第 2 次回答对"燃油附加费"的表述与另两次有差异（判 0），但人工比对发现**第 1、3 次包含近似表述却判了 2**——判卷模型对边界表述的判定本身不稳定。

后者是"机器阅卷必须人工抽检"的又一实证（round4 曾靠人工抽检抓到考卷错题，这次靠人工比对抓到判卷摇摆）。答案文本相似度 87.9% 佐证：同一问题三次回答措辞漂移不小（temperature=0.2 的设计内行为），判定稳定性比文本稳定性更重要，但判卷口径的确定性（temperature=0）并不等于判定结果的确定性。

### 7.4 L6 多轮首测：指代消解全对，判卷口径要跟着题型走

四组追问全部通过——"过了**这个期限**才发现多收了""**这单**要是当时保价了 1000 元""发现**它**外包装也破了"都正确消解并给出手册依据，多轮链路（短期记忆 → 指代改写 → 检索 → 引用）工作正常。

首判 CS-MT-01#2 被判"编造'发货后 30 天'"——实际是回答引用了 turn1 上下文里已确认的时限数字（指代消解的正常产物），严格单轮判卷口径把它误判为编造。**多轮题型的金标判卷必须带对话上文语境**，已在判卷 prompt 增加 L6 分支后重判通过。教训与 round4 一脉相承：新题型上线，先审考卷和判卷口径，再下系统结论。

### 7.5 信息点召回率的口径发现：计算题的"结果数字"不该算信息点

信息点缺失明细里，OP-L3-01（电子秤 5.012kg 校准题）缺"12、10"——"±10g"是手册里的规则（该覆盖），但"12g"是**从 5.012−5.000 算出来的结果**，手册里本来就没有，要求"召回块覆盖 12"是无理要求。L3 计算题的答案结果数字（135、240、12g）靠推理不靠检索，应从信息点里排除。当前 96.6% 的均值里混着这类失真（约 3~4 个点），修正口径后会更高。同理，正则抽取的裸数字（如"1"）粒度太粗，产生了少量噪声信息点。下一版信息点构造：L3 行排除结果数字、数字必须带单位。

### 7.6 结论

1. **系统状态**：端到端能力复现 round4（命中率/拒答双 100%），新增维度上——检索头部质量高（golden_rank 全 1）但尾部有同手册噪声（@K 45.1%）、生成基本忠实（97.8%）且零误拒、引用溯源完全可信（双 100%）、整体稳定（96%）但存在 2 个摇摆点。
2. **唯一真失败 OP-L4-01 的根因在检索侧**（关键表格块未进 top-K），不在生成侧——修检索（topK/阈值/查询改写）比修 prompt 更对症。
3. **下一轮动作**（按优先级）：①滞留件预警类问题的检索优化（把数值阈值带进检索词）；②topK 5→3 或 min_score 上调的 A/B 回归；③L3 信息点口径修正；④摇摆题（OP-L4-01/ST-L2-01）修复后加进冒烟集盯防回归。

## 八、局限与下一批

**本版已知局限（诚实清单）：**

1. **"资料"是近似**：分侧评审的上下文 = `/rag/search` 用原问题直接检索的 top-K 块；而 /ai/chat 链路内部会先改写（指代消解）再检索，真实喂给模型的块可能不同。若改写后的检索更好，忠实度会被低估。根因是 **API 不暴露链路内部状态**——建议 /ai/chat 加 debug 字段（改写后 query、内部命中、grader 判定），届时忠实度可对"真实上下文"评审。
2. **块相关性/信息点覆盖是 LLM 判定**：和所有 LLM-as-judge 一样有误判率，沿用"错题人工抽检"流程校准（本域答案高度数字化，误判率可控）。
3. **引用精确率假设单一出处**：多文档合法支撑的场景需要金标扩充"合法引用集合"。
4. **信息点自动构造粒度有限**：关键词+数字覆盖了本域核心（数字命根），但"规则性表述"的覆盖依赖人工关键词质量。
5. **稳定性只有 3 个样本**：够看"判定翻不翻车"，不够做统计检验；要更严可加到 5 次。

**下一批（已设计、未实施）：**

| 指标 | 方案 | 成本 |
| --- | --- | --- |
| 噪声鲁棒性 | 上传第 4 份"干扰手册"（同领域、相近措辞、不同数字，模拟旧版制度/别家 SOP），重跑考卷对比准确率与引用精确率变化，测完删除恢复现场 | 中（一次导入+一轮回归） |
| 权限正确性 | 建两个分属不同团队的账号，手册改为团队可见；A 账号问 B 团队专属题 → 必须检索不到/拒答；断言引用列表不含 B 团队文档。把"权限下推"从架构叙事变成可回归指标 | 中（建号+改可见性+断言脚本） |
| 并发吞吐 | 并发 N 路 /ai/chat（N=4/8/16），记录 P95 延迟与错误率——客户"一天几千次"的真实关注 | 低（一个压测脚本） |

| 多轮扩充 | 3 轮以上链条、跨手册跳转（"客服的时限和运营的处理各是什么"）、多轮后的主题漂移 | 低（加题） |
